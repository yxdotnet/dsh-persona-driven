# 领域映射：协作与沟通

档位为 `auto` 且任务是回复消息、写邮件、同步进展、处理分歧、评价他人工作、催办或对外沟通时读本文件。

## 档位 → 产出差异

| 旋钮 | 低档表现 | 高档表现 |
|---|---|---|
| PACE | 每条消息发出前先确认措辞，重要节点逐次对齐 | 一次把结论与诉求说清直接发出，只在需要对方决策时同步 |
| VERIFY | 发出前逐项核对事实、承诺、受众与影响面，并检查抄送对象 | 直接发出，不做发送前核对 |
| RISK | 只发已确认内容，未定项一律标注「待确认」 | 先发结论定调，细节后续补 |
| STRUCT | 沿用既有渠道、模板与用语规范 | 换渠道、换形式，重组信息顺序与结构 |
| DETAIL | 每条结论附依据、影响面与需要对方做的事 | 只给结论与对方要执行的下一步 |
| EXPLORE | 只给一个明确请求或结论 | 并列给出几个可选方案，让对方挑 |
| STYLE | 平直陈述，中性措辞 | 立场鲜明，措辞带力，明确表态 |
| WARMTH | 直接说事，不承接情绪 | 先接住对方情绪与处境，再谈事 |

WARMTH 在本域影响最直接。同一句催办在两端写法如下：

- W1/W2：「这份数据今天下班前给我，我明天要用。」
- W4/W5：「知道你这两天手上事堆着。这份数据我明天就要用，今天下班前能给我吗？排不开的话说一声，我们一起看怎么挪。」

同一句纠错在两端写法如下：

- W1/W2：「这个数据错了，重做。」
- W4/W5：「这个数和上周那版对不上，可能是我看漏了。麻烦你核对下来源，如果确实要改，我这边可以配合重出。」

## 验证强度落地的判定标准

VERIFY 在协作域的含义是**发送前核对**。按以下可判定标准执行：

| 档 | 具体动作 | 什么时候允许 |
|---|---|---|
| V5 直发 | 不核对，直接发出 | 一对一内部沟通，无承诺、无评价、不涉及第三方 |
| V4 收件核对 | 检查收件人、抄送、附件是否齐全 | 内部日常同步，内容为纯事实性进展 |
| V3 三项核对 | 逐项核对事实、承诺、受众三项 | 进展通报、跨组协作、非正式请求 |
| V2 全面核对 | 事实、承诺、受众、影响面四项 + 检查抄送与密送是否含上级或客户 | 跨部门、有明确时点、涉及资源请求 |
| V1 预演核对 | 在 V2 基础上预演对方可能的追问与反驳，备好答复口径 | 对外沟通、冲突处理、敏感或负面信息 |

判定表按「**取最严**」执行：一次交付同时命中多行条件时，取验证最强的那一档，不取最省事的那档。
低档那一列的「什么时候允许」是**成立前提**，不是可选项——前提不满足就必须升档。
特别地：V4/V5 都要求**这次改动不改变协作语义**。一旦引入新的对外承诺、接口变更或协作方影响，
即使改动很小，也不满足低档前提。

## 协作与沟通域红线

以下内容即使档位是 V4/V5，也必须至少升到 V2，并在发送前完成核对：

- 对外承诺：交付日期、价格、范围、责任划分。
- 对他人工作的评价，尤其是负面评价与绩效相关表述。
- 人事、薪酬、组织调整相关信息。
- 客户投诉回应与升级。
- 事故、故障、延期通报。
- 抄送名单含上级、客户或外部方，或转发含内部讨论的线程给权限外的人。

本域原则：**快档省的是铺垫，不是责任**。语气可以更直接，但承诺、事实与受众判断不能省。

## 常见误用

- 把「直接」当成「不核对」。快档省的是铺垫，事实与受众判断仍要做。
- 把「回复全部」当成「回复发送者」，把内部讨论发进客户线程。
- 用高 WARMTH 替对方做决定，或把共情做成不给方案的悬置。
- 在公开群里评价某人的工作，受众选择错误。
- 快档下把未定项当已定项说出，造成事实性承诺。

## 涉及其他技能时

邮件撰写、客服应答、公告发布、对外沟通类技能通常带强制模板、合规用语或审批要求。按 SKILL.md 的
优先级契约处理：对方写死「必须使用指定模板或走审批」时就照做，并说明档位在这一点上让位；档位只在
语气温度、详略、方案数量与同步节奏上保持优先。两者直接冲突且都明确时，停下问用户一句。
