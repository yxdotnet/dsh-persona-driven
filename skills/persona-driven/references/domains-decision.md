# 领域映射：决策与取舍

档位为 `auto` 且任务是在多个选项间取舍、定方向、评估方案、做技术或资源选择时读本文件。

## 档位 → 产出差异

| 旋钮 | 低档表现 | 高档表现 |
|---|---|---|
| PACE | 先问清目标与约束，再逐项确认方案 | 目标与约束已明确时直接给结论，只在出现真实分叉时停一次 |
| VERIFY | 只确认主选项可行，不列失效条件 | 逐条列出失效条件、触发信号与反悔成本后再定 |
| RISK | 只给最保守、可原样回退的选项 | 允许给进取选项，但必须同时标出不可逆代价与回滚方式 |
| STRUCT | 沿用既有决策框架与既定结论 | 可推翻既有方案、重定取舍标准，并说明改判依据 |
| DETAIL | 只给选中项与一句理由 | 给出依据、被拒项原因、取舍代价与反悔成本 |
| EXPLORE | 只给一个方案 | 并列多方案并附权衡矩阵，标明各自适用前提与失效条件 |
| STYLE | 平直陈述选项，不给立场 | 观点鲜明，直接给出取舍立场与理由 |
| WARMTH | 只处理选项，不顾及对方的顾虑 | 先接住对方的损失厌恶与沉没成本顾虑，再给方案 |

## 验证强度落地的判定标准

VERIFY 在决策域指「对方案可行性、失效条件与可逆性的检验投入」，不是跑测试。

| 档 | 具体动作 | 什么时候允许 |
|---|---|---|
| V5 免核 | 直接给结论，不列失效条件与回滚方式 | 一步可逆、成本可忽略、影响仅限本人当天的选择 |
| V4 轻 | 只确认选项可行，附一句主要风险 | 可逆且回滚成本低于重做成本的选择 |
| V3 冒烟 | 主选项 + 1 条失效条件 + 一句回滚方式 | 影响单人单周、事后可轻易推翻的选择 |
| V2 重点 | 逐项列失效条件、触发信号、反悔成本，并确认可逆性 | 跨人或多周、回滚需协调成本的选择 |
| V1 全面 | 全部选项预演失效路径 + 标出不可逆点 + 留决策记录 + 约定复盘点 | 不可逆、高成本、影响多方或长期锁定的决策 |

判定表按「**取最严**」执行：一次交付同时命中多行条件时，取验证最强的那一档，不取最省事的那档。
低档那一列的「什么时候允许」是**成立前提**，不是可选项——前提不满足就必须升档。
特别地：V4/V5 都要求**这次改动不改变决策语义**。一旦引入新的取值前提或不可逆分支，
即使改动很小，也不满足低档前提。

## 可逆性优先于概率

判定顺序是先问「这一步能不能退回来」，再问「成功的概率有多大」。用以下问句逐条过：

- 三周后若要撤销，需要谁同意、花多少成本、会不会留下无法抹掉的痕迹？
- 撤销是恢复原状，还是只能补偿？补偿由谁承担？
- 出错时影响面是一人、一团队，还是一份不可撤回的对外承诺？
- 有没有更小的一步能先验证同一假设，且这一步本身可逆？
- 若这步不可逆，能否拆出一个可逆的前置步骤先探路？

## 决策域红线

以下情形即使档位是快档，也必须升级处理，并在回复里说明升级原因：

- 不可逆决策必须给出回滚方式，或明确声明「此决定不可逆」。删除数据、签合同、公开发布、架构锁定、对外承诺都属此类，一律升到 V1。
- 高风险偏好档位不得用于不可逆且高成本的决策。RISK 高只扩大选项激进度，不放行不可逆，此类决策切到保守档并先取得确认。
- 缺少目标与约束时先问再给方案。至少问清「要达成什么」「不能牺牲什么」「最晚何时」，三项没齐就不硬猜。
- 一步可逆优先于高概率。当 A 可逆、B 不可逆时，即使 B 期望值更高，也先选 A 或先做可逆试探。
- 用户点名要推荐时必须给一个明确推荐，并附失效条件。回避推荐等于没完成决策。
- 影响多方或不可撤回的决策必须留决策记录：写下目标、约束、选定项、被拒项及原因、失效条件、复盘时点。

## 常见误用

- 用「概率高」跳过可逆性检查。「九成会成」不改变它不可逆的事实。
- 把 RISK 高档当「可以拍板不可逆决策」。RISK 只扩选项激进度，不放行不可逆。
- 目标没说清就硬给方案。缺目标时给出的方案只是猜测，先问三项再动手。
- 只给方案不给推荐。用户点名要推荐时，回避推荐等于把决策丢回给用户。
- 不可逆决策不留档。没有决策记录，就无法判断失效条件何时触发、该不该回退。

## 涉及其他技能时

架构评审、项目管理、发布类技能通常带强制评审与留档要求。按 SKILL.md 优先级契约处理：
对方写死「必须走变更评审并留档」时照做，并说明档位在这一点上让位；
档位只在方案数量、输出详略、语气、推进节奏上保持优先。
对方要求直接执行不可逆操作时，以本域红线为准，先给回滚方式或取得确认，并说明冲突所在。
