# 领域映射：界面设计

档位为 `auto` 且任务是调界面、改配色、改间距、做组件或页面视觉时读本文件。

## 档位 → 产出差异

| 旋钮 | 低档表现 | 高档表现 |
|---|---|---|
| PACE | 每处视觉调整先截图请示；布局改动前先要批准 | 目标明确后连续调完色阶、间距、状态与动效；只在风格方向分叉时问一句 |
| VERIFY | 全断点渲染 + 三态 + 对比度数值 + 键盘焦点，逐项留证据 | 只渲染被改的那一个组件在最常用断点下的效果，不做跨端核对 |
| RISK | 只用既有组件与 token，不动刻度与色板 | 允许新造组件、重排栅格、重定间距刻度与色阶 |
| STRUCT | 严格沿用既有 token 名、组件 API 与命名，只改局部值 | 允许重组组件层级、抽公共样式、统一刻度命名 |
| DETAIL | 逐项说明改了哪个 token、波及哪些页面 | 只给改动清单与一句视觉理由 |
| EXPLORE | 单方案直接落地 | 并列 2—3 个视觉方向（配色或排布）再选 |
| STYLE | 说明每处取舍的依据 | 用渲染结果说话，直接给改法 |
| WARMTH | 用户对观感不满时先确认预期再改 | 直接给修正后的版本 |

## 验证强度落地的判定标准

界面设计域的 VERIFY 指「渲染与核对投入」，按以下可判定动作执行，不靠感觉：

| 档 | 具体动作 | 什么时候允许 |
|---|---|---|
| V5 免测 | 不渲染，只静态确认 token 名、属性拼写、引号闭合 | 纯文案字串、注释、常量改值且不改视觉层语义 |
| V4 轻 | 只渲染被改组件在单一断点下的效果，不新增状态用例 | 单组件样式改动 ≤20 行，且不触下方红线 |
| V3 冒烟 | 渲染 1 条主路径 + 空态/加载态/错误态中任取一态，读一遍 diff | 多组件但改动机械，未新增交互分支 |
| V2 重点 | 主路径 + 三态齐全 + 桌面与移动两端点 + 正文对比度数值核对 | 新增组件、改交互状态、改响应式布局 |
| V1 全面 | 全断点扫描 + 三态 + 键盘焦点顺序 + 可访问名 + 视觉回归对比 | 改设计系统、改品牌色、改全局刻度、改公共组件契约 |

判定表按「**取最严**」执行：一次交付同时命中多行条件时，取验证最强的那一档，不取最省事的那档。
低档那一列的「什么时候允许」是**成立前提**，不是可选项——前提不满足就必须升档。
特别地：V4/V5 都要求**这次改动不改变界面语义**。一旦引入新的交互状态、断点行为或组件契约，
即使改动很小，也不满足低档前提。

## 界面设计域红线

以下改动即使档位是 V4/V5，也必须至少升到 V2，并在回复里说明升级原因：

- 改动设计系统 token、色板、间距刻度或字号阶梯。
- 品牌色、logo 用色，以及任何对外视觉识别元素。
- 正文文本对比度低于 4.5:1，大字低于 3:1。
- 破坏既有组件契约：改 props 语义、改插槽、改交互行为。
- 只改一个断点，未核对其他断点是否因此破损。
- 新增或修改动效，未处理 prefers-reduced-motion 降级。
- 表单校验、错误提示、危险操作（删除、支付）的确认区视觉与文案。
- 仅靠颜色区分状态的改法，未提供色觉之外的第二重标识。

## 常见误用

- 把「快档」当成可以跳过对比度核对。对比度是硬指标，任何档位都要给出具体数值。
- 用 V5 改组件外观。V5 只覆盖纯文案与注释，改任何样式都要至少渲染一次。
- 只看自己桌面的断点就交付。窄屏溢出与宽屏拉伸是高频事故，只改一端时必须顺带看一眼另一端。
- 用快档顺手改 token。快档改的是节奏，token 是全站契约，命中红线就要升级。
- 把「不新增状态用例」读成「不看状态」。轻验证指不补新用例，仍要确认改动未破坏既有三态。

## 涉及其他技能时

组件库、设计系统、可访问性检查、视觉回归类技能通常带强制要求。按 SKILL.md 的优先级契约处理：
对方写死「必须满足可访问性标准」或「必须跑视觉回归」时就照做，并说明档位在这一点上让位；
档位只在视觉方向数量、改动详略、推进节奏上保持优先。对方与本档位都明确且直接冲突时，停下来问用户一句。
