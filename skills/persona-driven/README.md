# persona-driven · 人格驱动引擎

用**人格档位**驱动 AI 的工作风格。把「AI 太谨慎、小改动反复测试、烧 token」这类风格问题，翻译成 8 颗可调的旋钮；一句「果断点」就能切档，减少反复确认与多余测试带来的等待。**（可选）**装上 DSH 插件后，档位在整个会话里稳定生效——**包括调用其他技能时**。

不懂 MBTI 也能用。MBTI 只是好记好叫的外壳，真正生效的是旋钮数值。

---

## 它解决什么

小改动也要跑全量测试、反复确认、写三套方案——消耗的是你的 token 和时间。这类问题不是能力问题，是**风格问题**：推进多快、投多少验证、给几个方案。

本技能把它参数化成 8 颗旋钮，你可以直接拧：

| 组 | 旋钮 | 回答的问题 |
|---|---|---|
| 执行 | PACE 推进节奏 | 多久停下来问一次 |
| 执行 | **VERIFY 验证强度** | **为这次改动投多少验证** |
| 执行 | RISK 风险偏好 | 愿意承担多大不确定性 |
| 执行 | STRUCT 结构约束 | 能不能动既有结构 |
| 认知 | DETAIL 细节粒度 | 说多细 |
| 认知 | EXPLORE 探索广度 | 给几个方案 |
| 交互 | STYLE 表达风格 | 怎么说话 |
| 交互 | WARMTH 共情温度 | 先照顾人还是先处理事 |

针对 token 痛点起决定作用的是 **VERIFY**。它与 PACE、RISK 联动：快节奏 + 高风容忍天然导向轻验证。

## 安装

本技能有三种交付层级，可以只装第一层，也可以叠加上去。

### A. 只装技能（始终可用，L1/L2 —— 能影响、不能约束）

> 本 README 里的所有命令都在**技能目录**下执行；在 DSH 会话里，技能目录由 `<skill_resources>`
> 的「Base directory for this skill: <绝对路径>」给出。

把 `persona-driven/` 整目录复制进任一 DSH 技能根目录即可，DSH 会自动发现，无需任何配置。
技能根目录按优先级从高到低（rank 数字小的先赢）：

1. `<projectRoot>/.dsh/skills`（项目级）
2. `<projectRoot>/.agents/skills`（项目级）
3. 组合（composition）里配置的任意 `customSkillDirs`
4. `$DSH_HOME/skills`（用户级；`$DSH_HOME` 默认 `~/.dsh`）
5. `~/.agents/skills`
6. 宿主内置（bundled）技能目录

`<projectRoot>` 指最近的、包含 `.git` 的祖先目录。装到**用户级**目录
（`$DSH_HOME/skills/persona-driven/`，即 `~/.dsh/skills/persona-driven/`）可让任意项目的任意会话都能用：

```bash
cp -r persona-driven "$DSH_HOME/skills/"
```

### B. 安装 DSH 插件包（L3 —— 每轮注入 + 安全底线强制确认）

`@dsh-external/persona-driven` bundle 提供：技能注册（`ctx.skills.registerProvider()`）、
原生 Cordis Host 半（`agent/pre-step` 每轮注入 + `agent/created` 时经 `agent.inject()` 做
SessionStart 注入）、以及原生安全底线（`tools/pre-execute` 返回 `{ kind: 'ask', reason }`，
交给 DSH 的 Approval 服务，用户真的会被问一次）。

```text
用 DSH 的 plugin_manager（install_bundle）安装 @dsh-external/persona-driven，
或把该 bundle 写进 profile 的 dsh.profile.bundles 后执行安装，然后重启 DSH。
```

**这条路不写任何 `settings.json`，也不需要额外的 shell 运行时。**

### C. 可选兼容桥（配置文件式钩子）

```bash
cd "$DSH_HOME/skills/persona-driven"
python scripts/persona.py doctor                                  # 先查环境
python scripts/persona.py install-hooks                           # 预览，不写盘
python scripts/persona.py install-hooks --apply --write-confirmed  # 执行
```

它把一份 Claude Code 格式的 hooks 配置写到 `$DSH_HOME/persona/hooks.json`
（**先自动备份**到 `$DSH_HOME/persona/backup/`），随后由你自己加一行 Cordis 配置，
mount `@deepseek-ai/dsh-hooks-claude-code` 并把 `configPath` 指向该文件。
桥接支持 `SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse` 四个事件，
**不支持 `PreCompact`**——压缩之后档位块不会再被重新注入；走 B（原生插件）不受影响。

命令名与路径均通过 `scripts/` 内的相对定位推导，不写死任何本机路径。

> 本仓库的这份文档是**从上游 Agent 平台技能包移植到 DSH** 的版本；上游与 DSH 的机制差异
> 已在 `references/setup-guide.md` 中逐条写明。

## 用法

**不需要记命令，用人话讲就行。**

| 想干的事 | 直接说 |
|---|---|
| 要快、别磨 | 「果断点」「别反复测试了」「token 烧太快」 |
| 点名人格 | 「用 ENTJ」「切到 ESFP」 |
| 用预设 | 「极速模式」「按稳的那套来」「多给我几个思路」 |
| 看/关 | 「现在是什么人格」「关掉人格」 |

> **提示：点名比暗示稳。** 触发是概率性的——同一句风格描述连说两次，实测可能一次触发、一次没有。
> 想让 AI 确定切档时，用「用 ENTJ」「切到极速模式」这类**点名**说法；
> 用「果断点」这类风格描述时，AI 拿不准会**先问你一句**，而不是沉默忽略——多问一次比切错好。

四个预设，不用记类型代码：

| 预设 | 档位 | 特点 |
|---|---|---|
| **极速** | P5/V4/R4/S4/D5/E1/ST3/W2 | 快、省、少问、少测、少废话 |
| **稳妥** | 高验证、低风险、按既有规范走 | 改动核心模块时用 |
| **探索** | 探索向：多方案、敢试新 | 需求还没想清时用 |
| **倾听** | 情绪优先：先接住人，再解决问题 | 想先被理解时用 |

16 型全集同样支持。八个领域（编码、界面设计、视觉图像、金融、写作、规划、协作、决策）各有一份档位→产出差异映射，按任务自动只加载相关的那一份。

**会话档位会累积，可定期清理**：每在对话里切一次档，`$DSH_HOME/persona/sessions/` 就多一个小文件（约 0.7 KB）。`python scripts/persona.py sessions` 列出全部；`python scripts/persona.py sessions --prune 30` 清理 30 天未更新的（默认只预览，确认后加 `--apply --write-confirmed`；**当前会话的档位一律保留**）。

**埋点目录里偶尔会见到 `.shard-` 后缀的文件**（`$DSH_HOME/persona/metrics/`），例如 `2026-09-25.jsonl.shard-12345`。那是并发写锁拿不到时的自保落点，**不是垃圾也不是损坏**：记录一条不少地写在里面，`persona.py report` 会自动算进去。想让目录干净，偶尔跑一次 `python scripts/persona.py compact-metrics --apply --write-confirmed` 把它折回主文件（默认只合并 1 小时未变动的分片，避免与仍在写的进程抢）。

## 怎么确认它真的生效

两个参照物：`get` 看档位有没有落盘，注入块看注入通道有没有在跑。

**① 档位真的写进去了吗** —— 跑 `python scripts/persona.py get`：

```text
人格：ESTP（type）
级别：l3   领域偏好：auto
档位：P5/V4/R5/S4/D5/E1/ST4/W2
更新：2026-09-24T15:14:10+08:00
```

**② 每轮注入块长什么样** —— 同一条命令的下半部分就是它（下面是真实输出；**样例随版本更新，
若与实际输出不符，以实际输出为准**）：

```text
—— 每轮注入内容 ——
[人格档位 P5/V4/R5/S4/D5/E1/ST4/W2 · ESTP]
定位：企业家：先干起来，跑通就是胜利
档位：推进节奏:直通 验证强度:轻 风险偏好:敢赌 结构约束:较自由 细节粒度:极简 探索广度:单点 表达风格:鲜明 共情温度:冷
验证强度原文：轻：只跑与改动直接相关的既有测试，不新增测试（引入新行为或修复缺陷时除外——此时验证必须固化：新增或修改一条可复跑的测试用例，不便写测试则留命令+期望输出，跑一次就丢不算证据）；仅限单文件 ≤20 行、不触领域红线、且这次改动本身已被既有测试覆盖的改动
思考步骤：①一句话确认改动的最终目标与影响面。 ②只给一个方案，不给备选。 ③动手前把改动面与验收判据一次定全——省下的调用来自「一次改对」，不来自「少做事」。 ④直接改，一次改到位；改完做静态确认（类型、语法、编译或读 diff）。 ⑤再跑与改动直接相关的一条主路径；额外验证可以省，验证下限不能省——引入新行为或修复缺陷时证据必须固化：新增或修改一条可复跑的测试用例，不便写测试则留命令+期望输出，并在收尾最后一行自报「验证：<证据与复跑方式>」（纯机械改动自报不适用），出现返工即补齐验证。
安全底线（任何档位都不得绕过）：命中 删除/覆盖、支付与资金、鉴权与权限、密钥与凭据、生产环境变更、数据库破坏性语句、不可逆操作 时，强制切回高验证并先确认，不得按快档直接执行。
验证下限（不随档位下降，且与全部旋钮解耦）：档位调的是「额外验证」的多少，不是「要不要验」。改什么至少验什么——本次交付对象本身必须被真实验证并给出可复核证据；改动一旦引入新的行为、事实主张、数据推导或交互状态，即不满足低档前提，按领域红线取最严档；修复缺陷必须留下能复现该缺陷的验证证据。证据要固化、可复跑，不能跑一次就丢：引入新行为或修复缺陷时，把验证固化为新增或修改一条可复跑的测试用例（不便写测试则留命令+期望输出）。而这条用例必须真的抓住这次改动——把本次改动退回后它应当失败；只跑一遍命令、或写一条无论如何都通过的用例，都不算证据。并在收尾最后一行自报「验证：<证据与复跑方式>」，纯机械改动自报「验证：不适用」。探索广度（EXPLORE）与推进节奏（PACE）只决定「给几个方案」「多久停一次」，不参与本下限的计算——不得因「只给一个方案」或「只求快」而少验。
一次到位（省调用的合法来源）：本档位省下的调用必须来自「一次改对」，不得来自「少做事」。动手前把改动面与验收判据一次定全，再一次改到位。若出现返工——同一处改了又改、或验证失败后回头再改——即视为先前的验证投入不足：此时必须补齐验证，而不是继续跳过。调用经济（只减次数，不减内容）：探查够用即止——先定清改动面再动手，不读与本次改动无关的文件；同一个文件不要重复完整读取，改完看一次差异即可确认。一次调用能做完的事不要拆成多次：多条验证命令（跑用例、把改动退回后看是否失败、看差异）尽量写进同一次调用。合并的是调用次数，不是验证内容——验证下限要求的证据一件都不能少。多处同类修改（跨文件重命名、同一常量或文案的多处替换）按文件合并处理：每个文件用一次批量编辑完成该文件内的全部改动，或用一条脚本一次改写完，逐处单独编辑同一段代码是调用浪费；批量改写后仍按验证下限核对全部证据。任务已点名要改的文件就直接读，不要先列目录找它；只在确实不知道位置时才搜索。同一套用例跑通一次就够，不要换个框架再跑一遍（如 pytest 跑过又用 unittest）。改动完成且验证通过即结束，不再回看代码、不再复述改动。
```

级别为 `off` 时这一节会写「(当前级别不注入)」。看到它，就说明档位没落盘或已被关掉——**注入通道那一轮不会注入任何东西**，档位只剩口头声明。

级别为 `l2` 时这一节**只有三条底线**（安全底线 / 验证下限 / 一次到位，无档位数值、无思考步骤）——
这是 v1.5.19 起的变化：此前 `l2` 完全不注入，于是收尾自报这类要求下发不到，`l2` 组的自报率只有 7%。
底线是「约束」而非「花样」，与档位高低无关，所以现在随 `l2`/`l3` 一起生效。
**2026-10-14 的 300 轮复测已验证这条通道打通**：`l2` 组收尾自报率 7% → **99%**。

**v1.5.23：给「一次到位」补上「调用经济」。** 此前的底线管住了「不可逆操作」「验什么」
「省下来的调用从哪来」，但**没有任何一条管『一次能做完的事有没有被拆成多次』**——
P3 的 300 轮逐轮调用序列显示，`l3` 组在探查阶段已经把调用压下来（读文件 5 → 2），
验证阶段却仍被拆成 3–5 次独立调用（跑用例 / 退回改动再跑 / 看 diff）。
这一版就在同一条底线里写明：探查够用即止、同一文件不重复完整读取、
多条验证命令**尽量写进同一次调用**——**合并的是调用次数，不是验证内容**。
该条款的效果**已实测（2026-10-14，400 轮 A/C 两臂）→ 判定不成立**：
聚合成本降幅 8.21%（CI [3.65, 12.40]%，闸门 25%），逐工具类型对 `l3` 组**零效果**
（Bash 3.94 → 3.92、Edit 2.85 → 2.84）。机制层的解释很直白：**`l3` 组在 P3 时（尚无本条款）
就已处于调用数地板**，「探查够用即止」模型自己已经做到。细则见 `references/limits.md`。
「三条底线」的划分不变（`调用经济` 属于「一次到位」这一条内部）。

## 安全底线不可绕过

命中以下场景时，**任何档位都强制切回高验证并先问你一次**：

删除与覆盖 · 支付与资金 · 鉴权与权限 · 密钥与凭据 · 生产环境变更 · 数据库破坏性语句 · 不可逆操作

人格只决定「多快多严」，**永远不决定「要不要先问一句」**。L3 启用时，这条由原生的 `tools/pre-execute` 前置钩子把命中调用转成人工确认（返回 `{ kind: 'ask', reason }`，交给 DSH 的 Approval 服务，ask 不阻断），不依赖模型自觉——**它保证的是「一定会问你一次」，不是「一定不让你做」**。

**还有一条验证下限，同样不随档位下降，而且与旋钮解耦。** 安全底线管「不可逆操作必须先问一次」，验证下限管「这次改动本身必须被验」：档位只压缩**额外验证**（多跑几遍、补测非关键路径），不压缩本次交付对象的验证；改动一旦引入新行为（新分支、新事实主张、新数据推导）就必须升档；修缺陷必须留一条能复现该缺陷的证据。**探索广度（EXPLORE）与推进节奏（PACE）不参与这个换算**——「只给一个方案」「只求快」都不是少验的理由。用户明确说「这次不用验」可以豁免，但技能要在回复里说明豁免了什么、风险是什么，不能靠档位默认值静默跳过。

**省下来的动作只能来自「一次到位」。** 这是 v1.5.15 加的第三条底线：本技能的快档应当靠「动手前一次定全、一次改对、少返工」省调用，**不得靠「少做事」**（跳过验证、少改 `tests/`）。出现返工——同一处改了又改、验证失败后回头再改——就视为先前验证投入不足，必须**补齐验证**而不是继续跳过。起因是一次 300 轮对照实验的归因：原先的降幅里有一部分其实来自「少改 `tests/`」（剔除该成分后净效应下沿 16%，低于 25% 闸门，且漏验证显著劣化）。**这条改动已于 2026-10-14 完成 300 轮复测：判定不成立**（净效应 31.5% 过线，但漏验证仍显著劣化 → 一票否决），**效果未获验证**，细则见 `references/limits.md`。

**v1.5.19（P3）复测（2026-10-14，300 轮）同样判定「不成立」**，但性质不同、且有实质进展：**漏验证 C 组 0/100 vs A 20/100、方向感知检验「满足」，`l2` 收尾自报率 7% → 99%**；未过线的是**条件① 净效应区间下沿 23.08% < 25% 闸门**（差 1.92 个百分点）。因此**对外仍不得宣称「已解决漏验证」或「机制有效」**，分项数据可如实披露并须注明整体判定不成立。

**v1.5.23（P4）的「调用经济」已实测、判定不成立**：2026-10-14 完成 400 轮 A/C 对照
（事前预注册 + 哈希冻结），**四条件中 ①③④ 未满足**。**不得说它「减少了调用」或「有效」**。
条款**保留但如实标注**——它零成本、无害，且守住了「不许为了省调用而少做事」这条底线
（漏验证 C 0/200 vs A 143/200、跑验证率与自报率全 100%）。

**v1.5.25（P5）在「调用经济」内追加三条点名式条款。** P4 失败后的调用级归因
（改用每轮原始事件流 `updates.jsonl` 拿到每个工具调用的真实参数）定位到两项具体浪费：
一是**开幕列目录**——任务已点名要改的文件，模型却先用 `ls -la <沙箱> && echo "---" && ls -la <沙箱>/tests`
看目录结构（1.09 次/轮，约合全部浪费的 2/3）；二是**同一套用例换框架重跑**
（pytest 跑过又用 unittest 重跑，占 36% 的轮次，是未注入组的 3 倍——**注入反而把验证冗余抬高了**）。
v1.5.23 的条款是「原则式」（「合并调用」），实测对 `l3` 组零响应；v1.5.25 改为「点名式」，
直接禁掉这两项动作，并补上「改完并通过验证即结束」。
**该加严条款已复测、判定「不成立」**（P5，2026-10-15，400 轮 / 2 批串行，审计 23 项全绿）：
聚合成本降幅 **8.02%**（CI [3.91, 11.88]%），**整个区间都在 25% 闸门之下**。机制层诊断是这批最有价值的产出——
条款① **生效**（「查看文件」1.09 → **0.80 次/轮**），但条款② **反向**（双框架重跑率 36% → **56%**），
总调用 C 降 0.11 次/轮而**对照组同期降 0.13** → **H2 相对 H1 净增量 ≈ 0**，且「H1 无效是因太原则」被证伪。
结论：**不得宣称它能降低调用次数**，并**不建议继续往注入块里加「点名式负面清单」**。
侦察与可行性判定见 `experiment/REPORT-P5-侦察-可压缩空间量化-2026-10-14.md`，判定见
`experiment/REPORT-P5-H2点名式条款-400轮判定-2026-10-15.md`（均为项目内文件、**未随包分发**）。

> **三条底线的强制力不同**：安全底线有原生前置钩子兜底（命中即转成确认）；验证下限与「一次到位」**都没有钩子兜底**，只是书面规则 + 每轮注入，依赖模型遵守。细则见 `references/limits.md`。

**误拦可以收窄，但不能关闭。** 默认扫描范围含文本内容字段，所以写文档时正文里出现 `rm -rf` 这类字样也会弹一次确认。设环境变量 `PERSONA_GUARD_SCOPE=exec` 可收窄到「命令 + 路径」，写文档不再误弹；代价是**写入含危险命令的脚本文件也不再被拦**。该开关只有 `all`（默认）/ `exec` 两个取值，**没有「关闭」档**，取值非法自动回落 `all`；变量须为系统 / 用户级、改后完全退出并重启 DSH 才对注入通道生效，细则见 `references/setup-guide.md`。

## 卸载

**路 B（原生插件）**：用 DSH 的 `plugin_manager` 卸载该 bundle，或把它从 profile 的
`dsh.profile.bundles` 里删掉再执行安装，然后重启 DSH。不涉及任何配置文件。

**路 C（兼容桥）**：不需要先退出 DSH——桥只写本技能自己的 `$DSH_HOME/persona/hooks.json`，
不再碰平台级配置（上游平台时代那处「配置文件被占用、写回抛 `PermissionError`」的限制已消失）。

```bash
cd "$DSH_HOME/skills/persona-driven"
python scripts/persona.py uninstall-hooks                           # 预览
python scripts/persona.py uninstall-hooks --apply --write-confirmed  # 执行
```

只移除本技能的钩子，**保留其他来源的 hooks 与其他所有配置项**（已用 install/uninstall 往返测试验证 11/11）。

只关档位、保留钩子（**在对话里关档要带 `--scope session`**，否则会关掉全局档位、把其他对话的人格一起关掉）：

```bash
python scripts/persona.py off --scope session   # 只关当前对话
python scripts/persona.py off                   # 关全局默认（仅当用户明确说「以后都别用」）
```

彻底删除：卸载插件或钩子后，删掉技能目录（`$DSH_HOME/skills/persona-driven/` 或项目级技能根下的同名目录）与 `$DSH_HOME/persona/`。

## 四条必须先知道的事

1. **核心假设已跑三轮实测，按判定线不成立。** 最新一轮 v3（300 轮 = 10 任务 × 10 重复 × 3 组，单一模型）：
   工具调用中位数 **12 → 7.5（下降 37.5%，95%CI 27%~50%）**，方向成立、剂量-反应单调；
   但**漏验证显著劣化**（C 79/100 vs 对照 48/100，p<0.0001），且效应强烈依赖任务类型（21%~56%）。
   **不要相信任何 token 降幅数字，也不得说「已解决漏验证」。**
   （判定口径已于 1.5.12 重定：旧线 −40% 溯源为设计文档的**举例句**、且落在实测 CI 内部，
   属统计上不可判定，已废止；详见 `references/limits.md` 与 `references/experiment.md`。）
2. **触发是概率性的。** 实测同一句话两次，一次触发一次没触发；显式点名稳定触发。
3. **L3 会改变本机的注入通道。** 路 B 会往一个 DSH profile 里装 bundle，路 C 会写
   `$DSH_HOME/persona/hooks.json`——这是它「真的能约束行为」的代价。装前知情，随时可卸载回滚。
4. **升级后哪些改动立即生效。** 档位数值与定位语是 `set` 时的快照——改数据源不会动已设档的用户，
   要重新 `set` 一次；而**验证强度原文与思考步骤是实时读数据源的**，文案修订立即生效、无需重设
   （这两项自 v1.5.1 起统一为实时读，此前思考步骤也是快照）。

完整声明见 `references/limits.md`——**上架说明与效果宣称一律以该文件为准。**
